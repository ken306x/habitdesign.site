# habitdesign.site Lo-Fi ビジュアルアイデンティティ 設計書

- 日付: 2026-07-21
- 対象リポジトリ: `~/Code/habitdesign.site`（`ken306x/habitdesign.site`・GitHub Pages）
- 作業ブランチ: `feat/lofi-visual-identity`

---

## 1. 目的

habitdesign.site の視覚言語を Lo-Fi（低忠実度）コンセプトで再構築する。

狙いは装飾の刷新ではない。習慣化デザインラボの中心命題は「興奮させるより、毎日自然に戻ってきたくなる体験をつくる」ことであり、Lo-Fi はその命題の視覚的な実装である。サイト自身が研究主張のデモとして機能する状態を目指す。

**Lo-Fi の解釈（決定事項）**

「粗さを乗せること」ではなく「テンポを落とし、反応の量を減らすこと」を本体とする。ノイズテクスチャは補助手段であり、主役ではない。

## 2. スコープ

**含む**

- habitdesign.site の全ページ（index / profile / publications / news / admissions / column / ohtalab / 事例4本 / apps / books / science / work-with-us / myplus10 / privacy）
- デザイントークン、書体、写真処理、モーション、フォーカス表示

**含まない**

- ロゴ（吹き出し型ループマーク）。2026-07-13 の復活バグ修正直後であり、同時に触ると巻き戻り事故の温床になる。現ロゴは紙色背景・オレンジと問題なく共存するため据え置く
- 本文コピー（`_src/data.js`）。視覚言語のみを差し替え、内容の議論と混ぜない
- スライドテンプレート、ハビタニア UI。ブランド全体への展開は本サイトの結果を見てから別サイクルで実施する

## 3. 決定した方向性

| 論点 | 決定 |
|---|---|
| コンセプトの階層 | ラボのブランド全体の上位コンセプト。本サイトはその第一実装 |
| Lo-Fi の強度 | B（紙と手）を土台に、A（間）の余白・テンポを骨格として組む |
| 和文書体 | 混成 — 見出し=明朝 / 本文=ゴシック / ラベル・数値=モノスペース |
| 写真処理 | 褪色＋粒子＋にじみを既定とし、人物写真のみ褪色のみに弱める |
| 実装スコープ | 全ページ同時移行 |

**採用しなかった案と理由**

- **C（テープとドット／暗背景・走査線・色ズレ）**: 最も「Lo-Fi らしい」が、共同研究先企業・受験生・学会に対して信号が強すぎる。テキストコントラストも落ちる。プロダクト側（ハビタニア）に限定する余地は残す
- **明朝単独**: 静けさは最良だが、和文明朝は文学部・老舗の連想が強く、AI/IoT を扱う工学系ラボとして保守的に読まれる
- **丸ゴシック単独**: 主張とは噛み合うが、研究の厳密さの信号が弱まり、企業向けの信頼を削る

## 4. 視覚言語

### 4.1 デザイントークン

`css/site.css` 冒頭の `.app{}` ブロックを差し替える。

| トークン | 現状 | 変更後 | 意図 |
|---|---|---|---|
| `--bg` | `#f5f4ef` | `#efe9db` | 紙。黄味を足す |
| `--surface` | `#ffffff` | `#f6f2e7` | **純白の全廃** |
| `--surface-2` | `#efece4` | `#e5ddc9` | |
| `--text` | `#17191f` | `#33302a` | インクの茶black |
| `--muted` | `#5c626c` | `#7a7264` | 青灰から温かいグレーへ |
| `--accent` | `oklch(0.72 0.155 52)` | `oklch(0.62 0.13 48)` | 彩度を落として褪色感 |
| `--cta-bg` | `#15171c` | `#2a2723` | 焦茶 |
| 角丸 | 14 / 20 / 999px | 4 / 6px | **ピル全廃** |
| `--sec-pad` | `6.8rem` | `8.5rem` | 息継ぎ |

**最重要は `--surface` の純白全廃。** 白いカードが紙色の背景に浮いている限り、粒子をいくら乗せても Lo-Fi にはならない。逆にここを潰せば、写真処理を弱めに保っても世界観が成立する。

角丸の縮小も同格に重要。14–20px の角丸とピル型ボタンは SaaS の記号であり、書体や色より先に「今風のテンプレ感」を生んでいる。

### 4.2 書体

| 役割 | 書体 |
|---|---|
| 見出し h1–h3 | Zen Old Mincho（新規） |
| 本文 | Zen Kaku Gothic New（現状維持） |
| ラベル・数値・英字小見出し | Space Mono（現状維持、露出を増やす） |

役割で分けることにより、Lo-Fi の温かさ（明朝＋紙）と研究室の厳密さ（モノスペースの数値・ラベル）を、雰囲気ではなく機能分担で両立させる。

既存の `data-font="mincho"` 分岐（`line-height:1.85` / `font-weight:600` / `letter-spacing:0`）が焼き込み済みのため、これを既定に昇格させる。

**Schibsted Grotesk は廃止する。** 和文フォント追加で4ファミリーになる負荷を避けるため、および欧文見出しを Space Mono に寄せる方が Lo-Fi の記号として一貫するため。ラテン専用グロテスクは本方向では役割を失う。

和文見出しの字間は `-.01em`（詰め）から `.04em`（開き）へ。和文を詰めるのは Hi-Fi の作法である。

### 4.3 質感

- **全面グレイン**: `body::after` に SVG `feTurbulence` を `opacity:.05` で1枚。意識に上らない強さに留める
- **写真（既定）**: 褪色（`saturate(.74) contrast(.93) brightness(1.04) sepia(.1)`）＋紙色オーバーレイ16%＋粒子20%＋周辺光量落ち。CSS の疑似要素で一括適用し、画像ファイルの再書き出しは行わない
- **写真（人物）**: 褪色のみ（`saturate(.78) contrast(.94) brightness(1.03)`）＋紙色オーバーレイ12%

「人物写真」の対象は、顔が識別対象として意味を持つ画像に限る。具体的には `members-2023.jpg` / `members-2024.jpg` / `members-2025.jpg` / `ohta.png`。`people-crossing.jpg` や `hero-walk.jpg` のように人が写っていてもイメージ写真として使われているものは既定側（褪色＋粒子）に含める。実装では専用クラス（例 `.photo-record`）で切り分ける。

人物写真を弱める理由は、ここだけ「世界観の統一」と「記録としての正確さ」が利益相反するため。配属生の集合写真は受験生が先輩の顔を見るためのものであり、質感を優先して潰すべきではない。

### 4.4 モーション

Lo-Fi のテンポの本体は速度低下ではなく **反応の量の削減**である。Hi-Fi な UI は触れたもの全部が反応する。Lo-Fi は動かないものが多い。

| 対象 | 現状 | 変更後 |
|---|---|---|
| `.reveal` | .8s / 16px | 1.15s / 8px |
| ヒーロー Ken Burns | 9s / scale 1.07 | 15s / scale 1.03 |
| スライドのフェード | 1.6s | 2.4s |
| `.ladder .cell` の pulse | 3.4s | 5.5s |
| `.domain` / `.col-card` / `.theme-chip` の hover | 枠線＋`translateY(-2px)` | 枠線のみ（`translateY` を除去） |

hover の変更は3箇所のみ。この3箇所は浮上と同時にアクセント色の枠線（`box-shadow:inset 0 0 0 1px var(--accent)`）を出しており、「押せる／今ここを触っている」という情報は枠線が担っている。`translateY(-2px)` は上乗せの装飾であり、除去しても伝達される情報は減らない。残り23箇所の hover は元から色変化・下線ベースのため変更しない。

`prefers-reduced-motion` の既存ガードは維持する。

## 5. アクセシビリティ（本設計に不可分な要件）

Lo-Fi は反応を減らす方向であり、**減らすほど静止状態の可読性への依存が増す**。以下は Lo-Fi 化とセットで実施する。

### 5.1 フォーカス表示の全面追加

現状 `focus-visible` の定義は858行中2箇所（`.domain` / `.bld-select`）のみ。`.col-card`、ボタン類、ナビリンク、フッターリンクにキーボードフォーカスの表示がない。マウスを使わない訪問者は現在位置を把握できない状態でサイトを移動している。

全対話要素に共通指定を入れる。

```css
:focus-visible{outline:2px solid var(--accent);outline-offset:2px}
```

これは Lo-Fi 化とは独立に存在していた欠陥であり、本作業で解消する。

### 5.2 hover のメディアクエリガード

`@media (hover:hover)` のガードが無いため、タッチ端末では hover 状態が指を離した後も貼り付く。全 hover 規則を囲う。

### 5.3 コントラスト

本文コントラストは WCAG AA（4.5:1）を下回らせない。`--muted` on `--bg` は数値上ぎりぎりになるため実装時に実測し、割れた場合は明度を下げる。

**この方向で最も起きやすい失敗は、褪色・淡色・低コントラストが積み上がり、味ではなく単に見づらいサイトになること。** 5.3 の実測がその防波堤である。

## 6. 実装

### 6.1 変更するファイル

| ファイル | 変更内容 |
|---|---|
| `css/site.css` | トークン、角丸、モーション、`focus-visible`、hover ガード、グレイン、写真フィルタ |
| `_src/build.js` | Google Fonts の読込 URL、`data-font="mincho"` を既定化 |
| 生成物 `*.html` | **直接編集しない。** `node _src/build.js` で再生成するのみ |

`css/site.css` は生成物ではなくソースである（`build.js` は cache-busting ハッシュの材料として読むだけ）。`_src/data.js` は無変更。

### 6.2 検証

1. `node _src/build.js` 実行後、`node _src/check-drift.js` で要素消失を確認
2. 全ページの目視確認（index / profile / publications / news / admissions / column / ohtalab / 事例4本 / apps / books / science / work-with-us / myplus10 / privacy）
3. コントラスト実測 — `--muted` on `--bg`、アクセント on 紙、CTA 帯の白文字
4. キーボードのみで全ページを回遊し、フォーカスが常に可視であることを確認
5. モバイル実機幅（375px）でグレインとフィルタの描画負荷を確認

## 7. リスク

| リスク | 対処 |
|---|---|
| **巻き戻り事故** — 生成物 HTML を直接編集すると次のビルドで静かに巻き戻る（2026-07-13 に実際に発生）。`check-drift.js` は要素の消失しか見ないため、スタイルの巻き戻りは検知できない | 作業は `_src/` と `css/` に対してのみ行う |
| **`filter` の描画コスト** — 写真28点に `filter` ＋ 疑似要素2枚を重ねる | 実機でスクロール性能を確認。劣化する場合は人物写真以外を静的な書き出し画像に切り替える |
| **「薄い」への転落** — 褪色の積み上げで単に見づらくなる | 6.2 の手順3（コントラスト実測）を必須ゲートとする |
| **ブランド分裂** — サイトのみ Lo-Fi 化し、スライド・ハビタニアが旧来のまま | 本サイクルでは許容する。展開可否は本サイトの結果を見て別途判断 |
